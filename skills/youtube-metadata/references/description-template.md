# Ship Shit Show Description Template

Use this reference for every YouTube description. The opening copy is also the reusable LinkedIn
body when Vincent asks for one description that works on both platforms.

## Research Basis

Reviewed on 2026-08-18 against 77 recent long-form descriptions from:

- [The PrimeTime](https://www.youtube.com/@ThePrimeTimeagen)
- [Theo - t3.gg](https://www.youtube.com/@t3dotgg)
- [Ben Davis](https://www.youtube.com/channel/UCFvPgPdb_emE_bpMZq6hmJQ)
- [Nerd Snipe](https://www.youtube.com/channel/UC2mPtIOYm1XihpmfrJKXjMw)

The stable shared pattern is:

1. A short, custom human opener about the actual video.
2. Optional sponsor copy.
3. Optional sources or useful links.
4. Optional chapters for long videos and podcasts.
5. A small evergreen link block.

Hashtag use was mixed: 43 of 77 descriptions used them, while Ben Davis used none in all 20
sampled uploads. Treat hashtags as an optional discovery aid, not part of the editorial opener.

The custom opener does the editorial work. The rest is utility. Do not turn the opener into a
table of contents.

## Core Description

Write 35-80 words across two or three short paragraphs:

```text
We [used / tested / built] [specific thing] for [real duration or task].

[One honest result or tension: it worked, but... / the launch claim was... / the expensive part was...]

This is what worked, what broke, and [the practical decision or lesson the viewer gets].
```

Adapt the sentence shape to the episode. Do not mechanically preserve the placeholders or force the
exact phrase `This is what worked, what broke` into every description.

## Writing Rules

- Lead with first-hand proof when the episode has it: `We used it for a week`, `We built it live`,
  or `We spent €X testing it`.
- Name the primary model, product, company, or business problem in the first sentence.
- Sound like a person describing why the video exists, not an SEO summary or generated agenda.
- Keep the core to one idea. Do not enumerate the whole program.
- Prefer one honest contrast: `It works, but...`, `The demo looked easy. The real workflow was...`.
- End on the viewer's decision, lesson, or saved effort.
- Do not write `In this video`, `Today we're going to`, `deep dive`, `game-changing`, or generic
  subscribe filler.
- Do not add headings, bullet lists, chapters, or links inside the core description.
- Use zero to three highly specific hashtags only when they add a useful discovery path. Put them
  on the final line, never inside the core copy. Prefer product or topic terms such as `#Grok46`,
  `#GrokBot`, or `#CursorOrigin`; avoid generic stuffing such as `#AI #Tech #Programming`.
- Keep `youtube_tags` separate from the public description; tags are metadata, not hashtags.

## Optional YouTube Utility Blocks

Append only the blocks the episode actually needs, in this order:

```text
[Optional sponsor sentence and one sponsor link]

Sources:
[One useful source per line]

CHAPTERS:
0:00 [Three words max]

[Optional artifact, repository, or channel link]

[Optional final line: zero to three specific hashtags]
```

- Do not add empty labels or placeholder links.
- Use chapters only when a timestamped transcript or VTT exists.
- Keep source labels short. A bare URL is acceptable when the destination is obvious.
- One useful artifact link is better than a wall of social links.
- YouTube may surface up to three description hashtags near the title, but they remain secondary to
  the title, thumbnail, and unique description. More is not better.

## LinkedIn Reuse

When the same copy must work on LinkedIn:

- Reuse the core description unchanged.
- Do not include YouTube-only utility blocks or `subscribe`.
- Decide LinkedIn hashtags separately; do not copy YouTube hashtags automatically.
- Add at most one final link, using the repository's LinkedIn UTM convention.
- Keep the first line under 200 characters so it survives the `see more` fold.
