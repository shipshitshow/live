## YouTube Description

Claude Fable 5 launched, so we tested it on the thing its name is basically begging for: games.

Last week we built a browser FPS with Opus 4.8 in one prompt. This time we pushed the idea further: an AI-native game studio with a shared universe, multiple game modes, a public repo, lore in markdown, reusable game systems, sprites, agents, and automation loops.

This is not just "AI made a game." The interesting part is the studio structure around it:

- one shared game universe
- multiple playable game experiments
- a monorepo with every game under `app/games`
- lore stored like an Obsidian vault
- agents that keep context across the whole project
- reusable systems for sprites, rules, animation, and gameplay
- a public repo people can inspect and fork

We look at what worked, what broke, where the sprites still bleed, why multiplayer makes everything harder, and why the next generation of indie game studios might look more like an agent harness than a normal game company.

If you build software, games, agents, or weird AI-native products, this is the part that matters: the model is not the studio. The loop is the studio.
